# Pending Tests

- API key input overflow: in the provider editor, toggle an API key visible and type or paste a long `sk-...` value; the text must stop before the eye button and never run under or past it, in both masked and visible states, at narrow drawer widths.

- Per-key model fetching: in the provider editor every API-key card shows a Fetch models button at its bottom right, next to the priority hint. Fetching uses only that key's credentials against the provider endpoint and merges the returned models into the channel list below; fetching with a second key accumulates into the same list, so the list is the union of both keys' models, deduplicated across keys and repeated fetches while keeping existing capability chips and request scripts untouched. Failures name the channel, account note and key ending. The button is disabled for a key with no value or a disabled key, and when the endpoint is empty. The former Select models button and its selection page are removed; capability chips and scripts are edited directly in the list as before, and adding model names manually is no longer available.
- Selection connect handle: marquee-select two or more nodes and a round plus button appears on the right edge of the dashed selection bounds, vertically centered. Dragging from it shows dashed curves from every selected node to the pointer, converging on a highlighted target. Dropping on an eligible non-selected node connects every selected node to it in one action, skipping invalid pairs (such as config to config) and already-existing links; dropping onto any selected node cancels the drag; dropping on blank canvas opens the connect menu, and choosing a type creates the new node at the usual left-edge-midpoint position connected from every eligible selected node. Escape cancels, W/A/S/D panning still follows the drag, and single-node handle dragging behaves exactly as before.
- Independent local-proxy routing: with local forwarding enabled from `https://www.suparkai.tech` or any other deployment origin, model, generation, media-download and WebDAV requests must go to the standalone `http://127.0.0.1:23210/<target-url>` service, never Canvas Agent's `17371/proxy`, and therefore must not receive Agent's `origin not allowed`. Running only `@basketikun/canvas-proxy` is sufficient; the Agent panel, chat connection and Connect token are unrelated. Agent conversation and canvas-control routes remain independently protected on port 17371 by their token and origin pairing.

## 图片分辨率尺寸表

选择分辨率和宽高比后，W/H 按下表填写，单位为像素。预设尺寸不受「16 倍数对齐」开关影响；该开关只控制手动输入尺寸时的对齐。最终生成尺寸以所选模型的实际输出为准。

| 宽高比   |              1K |              2K |              4K |
| -------- | --------------: | --------------: | --------------: |
| **1:1**  | **1024 × 1024** | **2048 × 2048** | **2880 × 2880** |
| **2:3**  |     1024 × 1536 |     1360 × 2048 |     2336 × 3520 |
| **3:2**  |     1536 × 1024 |     2048 × 1360 |     3520 × 2336 |
| **4:3**  |      1024 × 768 |     2048 × 1536 |     3312 × 2480 |
| **3:4**  |      768 × 1024 |     1536 × 2048 |     2480 × 3312 |
| **16:9** |      1536 × 864 |     2048 × 1152 | **3840 × 2160** |
| **9:16** |      864 × 1536 |     1152 × 2048 | **2160 × 3840** |
| **21:9** |      2016 × 864 |     2688 × 1152 | **3840 × 1648** |
| **9:21** |      864 × 2016 |     1152 × 2688 | **1648 × 3840** |

待验收：

- 在画布和图像工作台逐项切换 3 档分辨率与 9 种比例，W/H 应与表格一致，重新打开设置后仍选中正确档位；重点检查 1K 的 2:3、16:9、21:9 及对应竖图，以及 4K 的 1:1。
- 所有 4K 预设提交时均不应触发本地总像素或最长边限制；生成和编辑请求、调用脚本应收到所选像素尺寸。
- 分辨率为自动时保留比例选择，比例为自动时禁用 W/H；手动输入 W/H 后，对齐开关仍应按原有方式工作。
- Gemini 请求应带 aspectRatio（所选比例）；分辨率选了 1K / 2K / 4K 时应按尺寸表带上 imageConfig.imageSize，选自动时不带。质量不参与分辨率换算，视频尺寸设置保持原有行为。
- 图像质量可选自动与 5 档（低 / 中 / 高 / 极高 / 最高），请求里的 quality 字段应与所选档位一致，且尺寸不随质量变化。
